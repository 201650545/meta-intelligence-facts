# 03 · 方案构想：怎么把它搭出来

> 本页是 [[00-项目总览]] 的**实施层展开**：总览讲"策略长什么样"，本页讲"东西怎么摆、模板长什么样、闸门怎么交互"。
> 原则同总览：**不新造存放地**，全部挂在既有真源上。

## 一、组成件（五个，从便宜到贵）

| 件 | 形态 | 职责 | 何时才需要写代码 |
|---|---|---|---|
| **捕获器** | 会话内 prompt 规则（先不写代码） | 按 6 类信号打点，产出经验事件 | M3 若要做常驻旁路服务 |
| **判定器** | 一段固定 checklist（可写成 skill） | 四过滤 + 撞车检查 + 定层级 | M2 |
| **提炼器** | 三套产物模板（L1/L2/L3） | 事件 → 资产草稿 | M1（模板即可） |
| **落盘器** | 脚本（PowerShell / Python） | 写入真源 + git commit + 更新索引 | M1 |
| **召回器** | 记忆-技能协同规则（已有） | 命中 → 先查 skill 再临场发挥 | 复用现有，不重写 |

> **M0 只用前三件的"纸面版"**：我在对话里按规则打点，会话末尾给你清单，你勾一下，我用现成工具写盘。**不需要任何新代码就能验证闭环**。

## 二、目录与命名约定

### 2.1 本项目自身

```
D:\Work\AI自成长引擎\
├── README.md              # 陌生 Agent 入口
├── project.yaml           # 机器可读元数据
└── docs\
    ├── 00-项目总览.md      # 项目事实源（策略层）
    ├── 01-任务看板.md      # 路线 / 阶段 / 待决策
    ├── 02-原始想法记录.md   # 原话与证据（只增不改）
    └── 03-方案构想.md      # 本页（实施层）
```

### 2.2 待固化资产的中转区（关键设计）

自动产出**不要直接写进真源**，先进中转区，审校后再落盘：

```
D:\Work\AI自成长引擎\草稿区\        ← 2026-09-20 起实际落点（用户裁定；原设计写 D:\记忆\_inbox，已作废）
├── L1_经验\YYYYMMDD_[主题kebab].md          # 经验条目，静默写入
├── L2_SOP\YYYYMMDD_[动宾短语].md            # 流程草稿，须用户确认
└── L3_Skill\loomy-learned-[主题]\SKILL.md   # 技能草稿 = 缓冲区；提炼完成后【移动】到 技能库\ 并登记
```

- 好处：真源永远干净；审校压力攒批处理；误收可直接删中转文件
- **`技能库\` 是 L3 的唯一归口**，`草稿区\L3_Skill\` 只是写入缓冲（见 `经验沉淀SOP.md` §一 流转规则）
- **无 git → 用每日快照替代**（D5 结果）：`scripts\快照草稿区.ps1` 每日打包 `草稿区` 与 `技能库` 到 `_快照\`，保留最近 14 份，`_快照\快照日志.txt` 留痕（空目录也写 `.EMPTY.txt`，以区分"当天没产出"与"快照没跑"）
- ★ **落盘前必须先做撞车检查**：查 Loomy memory（`…\share\memory\<type>\`）、`D:\记忆\调度大脑记忆\`、`技能库\` 三处既有真源；命中同主题 → **走增补**（并在草稿头部标 `relates_to: <既有真源路径>`），**不新建平行条目**。否则同一知识会长出多份，检索时分裂

### 2.3 资产命名

| 层级 | 命名式 / 落点 | 例 |
|---|---|---|
| L1 | `<type>/<kebab-主题>.md` | `context/feishu-bitable-field-id.md`（沿用现有惯例，不破） |
| L2 | `docs/运行手册/<动宾短语>.md` | `docs/运行手册/磁盘迁移遗留目录废弃判定.md` |
| L3 | 落点 `技能库\loomy-learned-<kebab-主题>\`（暂存），skill 名 = `loomy-learned-<kebab-主题>` | `技能库\loomy-learned-npm-global-upgrade-redirected-shell\`（沿用现有惯例） |

> **重要**：L1/L3 命名继续沿用现有格式，skill id 命名继续用英文 kebab **不要另起体系** —— 否则新旧资产在检索时会分裂成两套。

## 三、产物模板

### 3.1 L1 经验条目模板

```markdown
# <一句话说清这条经验>

- **类型**：context / preference / workflow / pitfall
- **命中信号**（什么时候该想起它）：<可检索的场景描述，必填>
- **结论**：<怎么做 / 不能怎么做>
- **适用范围**：<项目名 或 全局>
- **来源**：<YYYY-MM-DD 对话摘要> + <相关文件路径>
- **计数**：命中 0 次 / 被推翻 0 次 / 最后命中 <date>
```

### 3.2 L2 工作流 SOP 模板

```markdown
# <流程名>

## 适用条件（什么时候用这个流程）
## 前置检查（缺什么会直接失败）
## 步骤
1. <动作> → **校验点**：<怎么知道这步成了>
   - 失败回退：<怎么办>
## 收尾
## 已知坑（本流程踩过的）
## 来源与验证记录
```

> L2 最常被写坏的地方：**只写"做什么"，漏掉"怎么知道成了"和"失败了怎么办"**。提炼器必须强制补齐这两项，补不出来就说明这条还不够格升 L2，退回 L1。

### 3.3 L3 skill 模板骨架

```
loomy-learned-<主题>\
├── SKILL.md        # description（触发词写全）+ 正文工作流 + 验证方式
└── scripts\        # 可选：可执行脚本
```

`SKILL.md` 必须包含的四段（缺一段不发布）：
1. **何时用**（description 里的触发词要覆盖我真实的说法，包括口语化说法）
2. **怎么做**（步骤 + 命令）
3. **怎么验证没坏**（dry-run 或自检命令）
4. **来源**（从哪次对话固化来的、原始事件 ID）

## 四、闸门交互（人在环的具体样子）

### 4.1 会话结束时的"建议固化清单"

```
本次会话建议固化 3 条：

[1] L1 · 含空格的飞书字段名会截断 JSON 参数 → 改用字段 ID
    信号：用 lark CLI 更新表格记录时
    落点：D:\记忆\context\  (撞车检查：与现有 feishu-bitable-field-id 重复 → 建议增补而非新建)

[2] L2 · 磁盘迁移遗留目录废弃判定流程
    信号：问"这个旧目录能不能删"
    落点：待生成草稿到 _inbox\待审草稿\

[3] L3 · 脚本：批量重算 Base 合计字段
    需要 dry-run，落 `技能库\`

回复要固化的编号（如 1,3 / all / none）
```

- **默认不写**：不回复 = 不固化（宁丢勿滥，符合 §G3）
- **显式一键**：我说「固化」/「记下来」→ 跳过询问，直接按上表执行
- **L3 强制两段**：先给 dry-run 输出，我说"好"才落盘 + commit

### 4.2 敏感信息处理

固化前扫一遍草稿：命中密钥 / token / 密码 / 手机号模式 → **自动替换为槽位名**（如 `{{LARK_APP_SECRET}}`）并追加一行「值存放在：资产清单 02 → 槽位 xxx」，同时在清单里对我明示"已脱敏"。

## 五、召回与衰减的具体规则

| 规则 | 阈值（初版，可调） |
|---|---|
| 命中一次 | `命中 +1`，刷新 `最后命中` 日期 |
| 我明确说"不对/过时了" | `被推翻 +1` |
| `被推翻 ≥ 2` | 降级：L3→存档、L2→退回 L1、L1→标 `disputed` |
| `90 天未命中` | 标 `stale`，复盘报表里单列，由我决定续命或删 |
| 撞车相似度 | 初版靠判定器语义判断，不引入向量库（避免为 M0 加基建） |

**每周复盘报表**结构：新增固化清单 / 命中 TOP5 / stale 清单 / 被推翻清单 / 判定器误报（我建议了但你会话里直接拒了）→ 最后一项用来调阈值。

## 六、明确不做的事（防范围膨胀）

- ❌ 不做全量扫描我的历史文档去"批量提炼"（成本高、噪声大、隐私面大）
- ❌ 不引入向量数据库 / 嵌入服务（M0~M2 靠语义判断够用）
- ❌ 不做多 Agent 共享的技能市场
- ❌ 不自动修改 handbook（规范变更必须我手写，跨项目影响面太大）
- ❌ 不让捕获器旁路上传任何东西到外部服务（全部本地）

## 七、开放的技术选型（等 M0 跑完再定）

| 选项 | 候选 | 决策条件 |
|---|---|---|
| 捕获器实现 | A. 纯 prompt 规则（会话内）B. Loomy 侧钩子 C. 本地常驻服务 | M0 用 A；若漏捕获率高 → B |
| 事件存储 | A. `D:\记忆\_inbox\` YAML B. 飞书多维表格 | 本地 A（可 git）；需要移动端查看则同步一份到飞书 |
| 落盘器语言 | PowerShell / Python | 跟目标真源所在环境走，Windows 本机默认 PowerShell |
| 复盘触发 | 定时任务（Loomy schedule）/ 手动 | 建议每周一自动出报表 |
