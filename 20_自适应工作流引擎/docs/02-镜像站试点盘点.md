## 四、★ 已失效证据：硬编码断言 vs 外部改版

手册 §三 自己写下了这两行警告（2026-09-15）：

> 模型 pill：`button.__composer-pill`（文本 Auto→**Thinking**）**⚠️ 2026-09-15 起菜单文案已变**
> 思考菜单项：`[role=menuitemradio]` → "Auto" / **"Thinking• Standard"** / "GPT-5.6 Luna" / "Configure..."。**已无 "Thinking• Extended"**；选中后 pill 文本＝**"Thinking"**（非 Extended），故 B 脚本的 `=== 'Extended'` 判定会误判

把警告和脚本逐行对：

| `evalB_ext.js` 行 | 硬编码断言 | 2026-09-15 后实际 | 后果 |
|---|---|---|---|
| L14 | hydration 闸门 `/^(Auto\|Extended)$/` | pill 文本是 `Model`→`Thinking` | `poll` 永远返回 null → 直接 `err:'pill-not-ready'` |
| L21-22 | 菜单项 `/Thinking.*Extended/i` | 只剩 `Thinking• Standard` | 找不到项 → 菜单空转 |
| L24-25 | `t === 'Extended'` 才算 ok | 成功切换后 pill = `Thinking` | **`ok:false` 误判**：流程其实成了，却报失败 |

**三重断裂，而唯一的"修复"是在手册里加了两行 ⚠️ 注释。** 脚本本体最后修改日停在 2026-09-06，比改版早 9 天。

> 这就是"不能自适应"的代价：**外部改了，我们的自动化静默变成错误信号源**——比完全报错更糟，因为它给出的是**假阴性**（`ok:false`）和**假阳性**（以为切到了 Extended 实际是 Standard），而纪律里写着"B 返回 `ok:true` 才可发"，于是整条送审链路要么被卡死、要么在错误模式下发问。

## 七、盘点结论（三句话）

1. **资产够厚、纪律够硬**，值得当试点；但**已经半自动**，项目目标必须定位在"自愈"而非"自动化"。
2. **失效不是假想**：`evalB_ext.js` 三处断言已在 2026-09-15 后全断裂，且产生的是**假信号**（比崩溃更危险）。
3. **探针有现成免费入口**（健康徽章端点，后端不随前端改版），所以 M0 阶段就能做出真实的 drift 检测，不需要先啃 UI 语义识别。

### ★ 根因更正（推翻契约 note 与执行方报告的归因）

契约 note 写「活跃卡不足：账号可能受限或会员到期」——**不成立**。证据链：

1. 健康端点返回的是**结构完整的真实 JSON**（schemaVersion/label/badge 齐全），不是反爬占位 → 数据本身可信
2. 「全部 Plus 失效」与会员到期日 2026-10-28（余 34 天）**矛盾** → 若会员真在有效期，不该全灭
3. 记忆中真实活跃卡号是 **CARD-23 / CARD-49 / CARD-11** 等更高段，而兜底枚举只探了 CARD-1..12（range [1,30] × max_probes 12 截断）

→ **根因 = 发现失败（池页 1 字节拿不到真实卡列表）+ 兜底盲枚举探错了卡号段**。break 状态本身**执行正确**（契约逻辑没被违反：min_active 未达即熔断），错的是**输入**。

### 下一步（三选一，待用户拍板）

- **A. 用户直接告知真实活跃卡号**（如 CARD-23），写入契约 `card_id_discovery.explicit_list`，复探即转绿 —— 最快、零风险
- B. 跑一次 **P2 UI 指纹探针**（需开浏览器许可）从池页拿真实卡列表 —— 顺带把 P2 也验收了，但要占用一次真人 Chrome
- C. 扩大枚举（range 上调至 [13,60] + max_probes 上调）—— **不推荐**：盲目刷接口且不知真实上限，可能又探 48 个灰卡

### 连带事实记录

- 池页对**无浏览器指纹的纯 GET** 返回 200/1 字节 —— `card_id_discovery.primary.method: html_regex` 对该页**永久无效**，不是偶发。将来契约应把它标注为 `requires_browser: true` 或改由 explicit_list/P2 供给
- 健康端点 `<MIRROR_HEALTH_API>/endpoint?carid=vip-NN` 对任意 vip-NN 都返回 200+JSON（哪怕是无效卡），**可用作卡号有效性校验器**——这是本次首跑白捡的一个能力

### 第二次更正（2026-09-24）：break 已解除 + 断言求值器 bug

- **契约新增 `explicit_list`**（CARD-23/49/11，source=记忆真源）——遵循「引用即校验」：记忆只作**候选输入**，真值以健康端点实测为准
