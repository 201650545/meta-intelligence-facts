# EXPERIMENTS

存放"验证某个改变是否真的更好"的完整记录。本阶段为空 —— 本轮做的是**事实普查与范围划定**，没有引入任何方案变更，因此没有实验。

## 什么时候必须开一个实验

上游规范里已有闸门（L3 需人点头 + dry-run），这里只补元智能要求的结构。**任何"换方案"性质的动作**都要先建实验，包括但不限于：

- 把某个技能的实体副本改成链接（须先有该宿主是否跟随链接的实测）
- 更换技能身份键判据、分类判据、范围判据
- 引入新工具或新分发器

## 命名

`EXP-<日期>_<kebab-主题>.md`

## 模板（八项必备，缺一不成立）

```markdown
# EXP-20260924_example

- hypothesis：为什么可能更好（可证伪的一句话）
- baseline：当前正式方案是什么
- candidate：实验方案是什么
- metric：怎么判断，阈值多少，谁测
- observation_window：观察条件与周期（禁止用一次 demo 宣布升级）
- risk：出错会怎样，如何回滚
- result：实测数据（不接受"看起来更好"）
- decision：adopt / reject / continue，并写明依据
```

## 两条硬规则

1. **先比较，再晋升。** 没有可比较基线时，第一件事是建基线，不是换方案。
2. **失败也要留档。** 它的价值是防止未来重复踩同一个坑 —— 本仓 `CHANGELOG.md` 的"自我纠错"表就是这个用途。
